# Transfer contract (implementation defaults)

These defaults refine the approved design; they are implementation decisions, not additional user requests. All REST paths are under `/api/v1`, camelCase JSON, UUID object IDs, lowercase SHA-256 hex. Access is authenticated; no browser download endpoint. Maximum file 20,000,000,000 bytes; default chunk size 4,194,304 bytes. Files are byte streams of any type; names are display metadata, never server paths. Zero-byte files have an empty manifest and the SHA-256 of empty bytes.

## Publication and metadata

`POST /files/uploads` accepts `{groupId,name,size,sha256,chunkSize,chunks:[{index,hash,size}],fileId?}`. It validates exact chunk indexes, lengths and total, creates a pending version, returns `{uploadId,fileId,versionId,missingIndexes}`. Each required chunk must have an upload-session receipt from that uploader's PUT; guessing another file's content hash cannot publish its bytes. Idempotent receipt retries remain valid. `PUT /uploads/{uploadId}/chunks/{index}` streams exact bytes, checks manifest size/hash and current permissions. `POST /uploads/{uploadId}/complete` verifies all receipts and full-file hash by streaming, then atomically publishes the version. The 30-day expiry starts at publication. Pending/incomplete uploads never appear as downloadable files. Existing FileService.CreateVersion may use this same flow.

`GET /files?groupId=...` lists authorized group files; `GET /files?scope=pool` lists the all-employee pool. File records include `{id,groupId,name,visibility,currentVersionId,createdAt,expiresAt,status}`. `GET /files/{id}/versions` lists accessible immutable versions. `GET /file-versions/{versionId}/manifest` returns `{fileId,versionId,name,size,sha256,chunkSize,chunks,expiresAt,visibility}`. `GET /files/{versionId}/chunks/{hash}` is the authenticated streaming fallback; permissions and current lifecycle checked before each response.

`POST /files/{id}/promote` admin only clears expiry on all retained versions, sets visibility pool and preserves original group reference/history. `DELETE /files/{id}` marks unavailable immediately; chunk deletion waits until no live references. Explicit version deletion/lifecycle must not break other files sharing hashes.

## Desktop boundary

Resumable upload also uses `GET /uploads/{uploadId}` to fetch `{uploadId,fileId,versionId,missingIndexes,completed?}`. It requires the original uploader and current upload permission. Completed uploads report completion and no missing indexes; client retries cannot create duplicate published versions. A paused upload persists this ID and resumes missing receipts.

The Rust background service owns authentication, refresh, API requests, local task DB, chunk cache, peer connections and progress events; React does not own network/file sockets. Public addresses and domain names require HTTPS/WSS. As approved for trusted LAN use, explicit HTTP/WS is accepted for RFC1918 IPv4 literals and loopback addresses; an omitted scheme still defaults to HTTPS. LAN HTTP does not encrypt login, chat or server file traffic; peer DataChannels remain encrypted. Native commands include `login`, `logout`, `api_request`, `start_download`, `start_upload`, `pause_transfer`, `resume_transfer`, `set_sharing_policy`, `list_transfers`. An interactive OS file picker supplies upload/download paths; no server-provided path is trusted. Login accepts `{serverUrl,username,password,deviceId?}` and returns a session view. Sessions stay in native memory initially; use the OS credential store for remembered login.

`start_download(version_id: String,destination: String)->task_id` and `start_upload(group_id: String,source: String,file_id: Option<String>)->task_id` schedule work without blocking window commands. Task snapshots/events have `{id,direction,versionId,name,state,bytesCompleted,totalBytes,activeSources,error?}`. States: queued, hashing, transferring, paused, verifying, completed, failed. `transfer.updated` events are emitted after durable verified progress. Task records store server/account identity and destination; restart must not transfer one employee's tasks as another. Do not overwrite an existing destination without explicit user selection; use a sibling partial file and atomic completion.

Verified partial chunks become shareable immediately, before entire-file completion. Server and peer sources can run simultaneously; distribute distinct chunks to initial peers to encourage diversity. Received data must match server-authoritative immutable manifest. Never advertise unverified content. Final file SHA-256 is also checked. Background cache is separate from saved destination; expiry and eviction remove cache only. Resume revalidates cached chunks.

## P2P integration decisions

WebRTC DataChannel with ICE (LAN host candidates, STUN reflexive candidates, configurable TURN relay) provides encrypted data transport. Same connection handles framed per-chunk requests/responses with bounded frames and buffered-amount backpressure, not an entire chunk/file JSON blob. Pairwise signaling travels over the authenticated server WebSocket. TURN credential configuration is supplied by administrator; absent TURN still permits server fallback. Desktop peers never accept requests without a short-lived recipient/device/file-version grant, validated at the current server by the serving peer; expiry or revoked membership stops subsequent requests. Presence claims are candidate hints, not trusted proof of bytes. Peer/disconnect/bad hash retries requeue only incomplete chunks.

Use one relay mechanism: configured TURN relays the encrypted peer channel; do not invent a second custom server relay that duplicates TURN. Server file streaming remains the reliable fallback and concurrent source. Native peer code and server signaling must support a deterministic local three-peer test (distinct initial chunks, reuse before completion), invalid hash, disconnect and fallback. External NAT success depends on actual network conditions; distinguish automated local verification from real public-network testing.

Native SharingPolicy is `{enabled:boolean,cacheQuotaBytes:number,maxConcurrent:number,bandwidthLimitBps:number,autostart:boolean}`; defaults true/10GB/3/0(unlimited)/true. `get_sharing_policy` reads it; native validates and persists settings. `send_server_event(event:JSON)` sends authenticated chat/signaling messages.

File listing records also include `createdBy` (uploader account UUID), `size` (current version bytes), and `sha256`. Use `createdBy` consistently for own-delete controls; backend always enforces actual privileges. Native TaskSnapshot `activeSources` is an array of source names; UI derives count from its length.

## Employee directory consumed by desktop UI

`GET /api/v1/users` returns enabled employee directory entries `{id,username,email}[]` to an authenticated user. Group owners use these IDs in existing group member POST/DELETE operations; this directory does not return password state, sessions, or privileged account controls. Administrator account management uses the separate `GET /api/v1/admin/users` endpoint with full user metadata.

## Native event channels

Internal service/UI subscription names stay dotted (`server.event`, `connection.changed`, `transfer.updated`, `chunk.verified`, `sharing.changed`, `sharing.revoked`, `service.error`). The actual Tauri transport maps dots to colons on both send/listen boundaries: `server:event`, `connection:changed`, `transfer:updated`, and so on. Tauri forbids dots in event channel names. JSON payload fields such as `type:"message.created"` and filenames remain unchanged.

## Peer registry and negotiation

Authenticated `POST /p2p/announce {versionId,indexes}` replaces the current device/version availability; heartbeat every20seconds and source lease60seconds. Verified cache changes trigger announcements immediately, including partial downloads. Withdraw removes one version or all own announcements. `GET /p2p/sources?versionId=...` returns authorized live device/user/index hints plus ICE configuration; immutable hash/size comes only from the file manifest. `GET /p2p/config` returns configured STUN/TURN or an empty list for LAN-only use.

Dedicated authenticated WebSocket `/api/v1/p2p/ws` relays scoped `peer.offer`, `peer.answer`, `peer.ice`, `peer.close` with UUID `connectionId`, `versionId`, `toDeviceId` and payload. Server-stamped `fromDeviceId`/`fromUserId` identify the remote endpoint; never accept caller-provided origins. Each connection is bound to one pair and one version. Refresh rotates sessions: reconnect and reannounce with the current credential.

`POST /p2p/grants {versionId,chunkHash}` returns the signed recipient grant; `POST /p2p/grants/validate {grant}` is called by the authenticated serving peer before every chunk. The serving peer also binds grant user/device to the trusted remote identity from signaling and matches version/hash/size to the request. TURN is optional; configure `LINKNESTX_ICE_SERVERS`, optional `LINKNESTX_TURN_SHARED_SECRET` and `LINKNESTX_TURN_CREDENTIAL_TTL` (default10m).


## Initial download allocation amendment (Task8 review I1)

Authenticated `POST /api/v1/p2p/allocate {versionId,taskId}` returns `{startIndex,endIndex,expiresAt}`: a half-open contiguous initial region from the immutable manifest. Both IDs must be UUIDs; actor, current session, device and version read ACL are checked before allocation. The server chooses the least occupied of `min(3,chunkCount)` regions among live leases, so the first three distinct devices receive disjoint regions for files with at least three chunks even when device IDs collide under any hash. Zero chunks return `[0,0)`. Later devices share the least occupied region. Leases last 60 seconds, are keyed by version plus trusted device, and same-device retries/concurrent tasks reuse the live lease without extending it. Global live capacity is 1024; lazy and periodic cleanup prune expired entries. State is in memory and resets on server restart. This scheduling hint never authorizes reading or advertising bytes.

Native cold downloads request allocation under a three-second overall discovery/allocation deadline. The first concurrent batch stays entirely within the assigned region (one request for a three-chunk file). After verifying and advertising that batch, the client waits at most one second for another partial source, refreshes discovery, then continues normal concurrent peer/server work. Coordination unavailable, full, or invalid responses leave authenticated server fallback available. Server restart or lease expiry may permit overlapping work across different allocation epochs; within a live epoch the first three distinct devices are disjoint.

Routine authenticated server `peer.close` with `code:"expired"` ends that connection. Native closes it, retries the interrupted request at most once with a fresh connection UUID/grant, and keeps source failures on a short cooldown instead of permanently excluding healthy devices. Wrong size/hash stays quarantined for the download. Existing server pair expiry and authorization semantics remain unchanged.

## Final administration and lifecycle contract

Migration 007 defaults existing files to `listed=true`, adds authoritative sharing policies, and preserves prior client transfer rows while allowing logical completion. Administrators receive all groups with `isMember`; member lists and files can be managed without joining. Ordinary chat history/send/socket delivery still requires membership. Nonmember management UI opens files and never mounts chat. `membership.changed` has a unique eventId; the removed/added target receives a content-free self notice, current members receive the authorized group notice. `files.changed` is a generic authenticated invalidation signal carrying no file/group/content identity.

Administrator `PATCH /files/{fileId} {name?,listed?}` edits a pool display name or reversibly unlists/re-lists it. Version names, sizes and hashes never change. Unlisted pool files retain permanent bytes/history and are inaccessible to ordinary employees including origin members. Administrators retain list/edit/replace/relist/delete access. Unlisting does not restart the 30-day group lifetime. Every metadata/listing change is audited.

Administrator `GET|PUT /sharing-policies/{scope}/{targetId}` uses scope `group` with a group ID or `pool` with a pool-file ID. Policy is `{enabled,maxConcurrent,bandwidthLimitBps}`, default true/0/0; zero caps mean unlimited and concurrency is bounded to 32. Promoted pool policy replaces origin-group policy. Effective sharing is local enabled AND admin enabled, with minimum positive caps; native enforces local aggregate bandwidth and a per-version admin aggregate. Policy disables advertisements, discovery, offer/connection permission and current per-chunk serving grants with HTTP 409, while authorized HTTP file downloads remain available. Client local pause is preserved.

Native lifecycle checks run on login, content/membership signals/reconnect, and every 30 seconds, independently of UI or local sharing. At most 16 distinct managed versions are checked per pass using three-second request deadlines and round-robin selection; N versions take at most ceil(N/16) passes absent additional event wakes. Denied 403/404/410 clears managed cache, in-memory manifest/discovery and version connections, and cleans exact task-owned `.linknestx-<UUID>.part` siblings after cancelling active workers. Saved final paths never enter cleanup. Canonical parent checks and non-symlink regular-file checks fail conservatively. Network/timeout/5xx does not erase valid data. Authoritative promotion refreshes cache expiry before reading. Pending uploads keep their earlier 30-day local expiry. Content-addressed quota remains bounded on storage/local policy changes. Explicit cancellation and service quit stop maintenance.

Messages project `fileVersionId`, `attachmentName`, `attachmentSize`, `attachmentStatus` (`available|expired|deleted|unlisted`). The UI saves the exact immutable version and follows its task progress. Reconnect and invalidations refetch authorized chat projections so old messages reflect current lifecycle; expired message content does not gain attachment metadata through this projection.

## Completion and background status

Every native server chunk request carries the actual task UUID in `X-Transfer-ID`; observed server bytes remain per-response traffic (retransmitted bytes are real traffic). Verified source contribution remains cumulative/max-idempotent per source and bounded by version size. A separate client claim `{taskId,versionId,nodeId:"local",action:"download.completed",bytes:fullVersionSize}` records one successful save after whole-file verification, final authorization and no-clobber publication. This covers cache-only and zero-byte saves without inventing remote bytes. Duplicate logical completion is idempotent; persisted completed tasks recover an interrupted audit outbox write. The known crash window between hard-link publication and durable completed bookkeeping remains a limited recovery case, with the saved destination preserved.

`get_background_status` returns `{sharingEnabled,activeUploads,error,lastCompletion}` under the local main-window IPC capability. Native service errors are retained even when React is closed; current upload permits emit `sharing.activity`, and the tray reflects errors/actual uploads/idle/pause. Supported UI channels include service.error, service.status, sharing.changed, sharing.activity, sharing.revoked and peer.sent. Transfer activeSources is explicitly labeled historical contributors used.

Hidden-window completed-transfer, service-error and membership-change notifications originate in the native lifetime, use bounded deduplication, and contain only generic text. Visible events are remembered without notification replay. macOS uses UserNotifications and Windows uses toast APIs with `com.linknestx.client`; notification permission/delivery failures become status errors without a notification-error loop. No shell or filename/message interpolation is used. These APIs compile from cached dependencies; actual OS permission prompts/toasts, installed Windows AppID behavior and Windows builds require platform runtime validation and are not established by mock/reducer tests.
