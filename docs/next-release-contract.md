# LinkNestX collaboration API contract

This document describes the shared desktop and browser API introduced in version 0.2. All routes are same-origin `/api/v1`. JSON errors use `{error:string}`. Protected requests use desktop Bearer or browser cookie; never both.

## Identity and contacts

`Profile` is `{id,username,email?,roles?:string[],disabled,createdAt,mustChangePassword,accountNumber:string,displayName:string,avatarUrl?:string}`. New account numbers are unique random six-digit decimal strings. Existing numbers are retained. Native administrators can supply an optional accountNumber when creating an account, or use PATCH /admin/users/{userID}/account-number with accountNumber to change it; custom values contain 6–10 digits with no leading zero. Numbers cannot collide with another account number or a username login alias. Updates preserve the user ID and sessions, are audited, and publish profile.changed after commit. `GET /profiles/{userID}` returns Profile; `PATCH /profile {displayName}` returns own Profile (desktop only); `PUT /profile/avatar` accepts raw PNG/JPEG, at most 2 MiB, returns own Profile (desktop only). `GET /profiles/{userID}/avatar` returns normalized PNG under authentication. Avatar URLs always use that same-origin path.

`GET /contacts/search?accountNumber=...` returns Profile or 404. `GET /contacts` returns `{friends:Profile[],incoming:FriendRequest[],outgoing:FriendRequest[]}`; pending requests only in incoming/outgoing. `FriendRequest = {id,from:Profile,to:Profile,status:'pending'|'accepted'|'rejected'|'cancelled',createdAt}`. `POST /friend-requests {accountNumber}` returns FriendRequest (201, including retry). `POST /friend-requests/{id}/{accept|reject|cancel}` takes `{}` and returns FriendRequest (200). `DELETE /contacts/{userID}` returns 204 and preserves old direct history.

## Conversations and receipts

`GET /conversations` returns `Conversation[]`: `{id,kind:'group'|'direct',title,avatarUrl?,peer?:Profile,memberCount,unreadCount,lastMessage?:Message,canSend:boolean}`. Only joined groups and own direct pairs appear. `POST /conversations/direct {userId}` returns Conversation (200), requires current accepted friendship. Direct id equals internal groupId; ordinary group management cannot list or mutate direct pairs. File upload uses this id; current friendship required for new direct messages/uploads, while existing history remains accessible after deleting friendship.

`GET /conversations/{id}/messages?before=&after=&limit=50` returns `{messages:Message[],nextCursor:string,hasMore:boolean}`. Opaque cursors match `Message.cursor`; before/after are mutually exclusive. No cursor selects newest page; messages within every page are ascending. Before page nextCursor is its oldest item; after page nextCursor its newest. Limit 1–200. `POST /conversations/{id}/messages {clientMessageId,body}` returns Message (201).

Message preserves `{id,sequence,groupId,senderId,clientMessageId,body:string|null,createdAt,expiredAt?,cursor,fileId?,fileVersionId?,attachmentName?,attachmentSize?,attachmentStatus?}` and adds `{conversationId,sender:Profile,readCount:number,readByMe:boolean}`. Messages also carry kind (text or system) and an optional systemType. Group creation, membership changes and role changes persist system messages in the same transaction as the change; their event payload includes the message ID as eventId. System messages are read-only. Expired messages expose no content. Own messages are excluded from readCount and unreadCount.

`POST /conversations/{id}/read {messageIds:string[]}` (1–100 IDs, duplicates allowed) returns `{messageIds:string[]}` of confirmed unique IDs. Validation is atomic: foreign/expired/unknown IDs reject whole batch. Exact IDs, no implicit sequence frontier. `GET /conversations/{id}/messages/{messageId}/readers` returns `{readers:(Profile & {readAt:string})[],count:number}`. Count and list use current enabled entitled members and exclude sender. Reads survive leave/rejoin; expired-message records are removed during retention.

WebSocket `/ws` automatically pushes every currently entitled conversation; accepts `ping` and `message.send`, and keeps existing `{type:'message.created',groupId,message}`. Add `conversationId` to message payload. New invalidations `{type:'contacts.changed'|'profile.changed'|'conversation.changed'|'read.changed',groupId?,conversationId?,userId?,messageIds?}` require REST reload. Contact/profile changes target entitled users; conversation/read events target currently entitled members. Browser socket uses same-origin cookie and mandatory exact Origin, no tokens in URL.

## Browser session

`POST /web/login {username,password}` (username also accepts accountNumber) requires exact same-origin `Origin`; sets `lnx_web` HttpOnly SameSite=Strict Path=/ cookie (Secure on HTTPS; trusted configured proxies may supply exactly one X-Forwarded-Proto, otherwise forwarded protocol is ignored). Returns `WebSession = {user:Profile,expiresAt:string,csrfToken:string,capabilities:{upload:false,p2p:false,adminWrite:false,profileEdit:false,nativeTransfers:false,updates:false,maxDownloadBytes:1000000000}}`. No bearer or refresh token in response JSON. `GET /web/session` returns same WebSession. `POST /web/refresh {}` rotates cookie and CSRF, returning same DTO. `POST /web/logout {}` revokes session, clears cookie, returns 204. Web session / logout / refresh remain available before initial password change; `/auth/password` is permitted with browser auth and CSRF.

All browser writes require exact same-origin Origin and `X-CSRF-Token`; refresh/logout included. Browser credentials persist a server-side web capability type, and native token/refresh routes cannot elevate it. Browser requests may read conversations/contacts/profiles/files/groups/me and own devices, send messages/friend actions/read receipts, change their own password, revoke their own devices. Upload/P2P/administrative writes/avatar/profile edits are denied server-side. Native manifest/chunk/grant routes are denied to web sessions; file metadata remains readable.

`GET /web/files/{versionID}/download` streams an authenticated file with Content-Disposition and known length, requiring size <= 1,000,000,000. One active stream per browser session; a concurrent stream returns 409, oversize returns 413. No Range support (Range rejected 416). HEAD checks metadata without claiming transfer. ACL/session checked repeatedly while streaming; cancellation releases stream slot. Browser saves are managed by the browser, and server completion does not assert a local save.

## Web assets and client releases

Public release routes are `/downloads`, `/api/v1/releases`, `/releases/...` and `/updates/{platform}/{arch}/latest.json`; the root serves the product homepage. `config.Config.WebAssetsDir` (environment `LINKNESTX_WEB_ASSETS_DIR`) configures SPA `/app/` serving. Unknown `/api/...` always returns 404. The static directory contains the built frontend only; missing assets return 404 and non-asset application paths fall back to index.html. Release assets are generated with the [offline publication tool](update-format.md) and served from `LINKNESTX_RELEASE_DIR`.

## Markdown documents

`GET /documents?scope=feed|mine|drafts|public&q=&cursor=&limit=20` returns `{documents:Document[],nextCursor,hasMore}`. Default `feed` lists readable published documents; `mine` includes the caller's published notes and drafts; `drafts` lists their drafts; `public` lists administrator-curated notes for authenticated employees. Search matches title and body, up to 200 characters. Limit is 1–50. Cursors bind the scope and search and order by update time and ID descending.

Lists include at most the first 2000 characters of the body, a `bodyTruncated` flag, and an empty attachments list. Open the individual document before reading or editing it.

`Document = {id,title,body,visibility:'private'|'friends'|'team',status:'draft'|'published',curated,revision,bodyTruncated,author:{id,username,displayName,accountNumber,avatarUrl?},createdAt,updatedAt,publishedAt?,canEdit,canDelete,canCurate,attachments:File[]}`. `GET /documents/{id}` returns the full document, with all published attachment versions. Each attachment has a `versionId` identifying that immutable version and a `currentVersionId` identifying the logical file's latest version. Resolve links and list keys by `versionId` so a replacement does not break older Markdown links. `POST /documents {title,body,visibility,status}` creates one; `PATCH /documents/{id}` accepts the same full fields plus the expected `revision`. Titles contain 1–200 characters after trimming; Markdown is at most 1 MiB UTF-8. `DELETE /documents/{id}?revision=N` deletes it and its attachments. A stale revision returns 409. Drafts and private notes remain owner-only, including against administrator reads; friends-only access follows the current friendship relation. Notes and their published attachments do not expire automatically.

`POST /documents/{id}/curation {revision,curated}` requires a native administrator session. Only published team-visible documents can enter the public library. Curation locks changes and deletion of the document and its attachments to administrators, including upload replacement and existing file routes. Removing curation restores the author's management rights. Curated documents must remain published and team-visible. Browser sessions can create and edit their own text notes but cannot perform administrator curation or modifications to curated notes.

Native uploads pass exactly one of `groupId` or `documentId` to `/files/uploads`. Document attachments have `visibility:'document'`, `groupId:''`, `documentId` and `expiresAt:null`; they publish without a chat message. `GET /files?documentId=ID` lists accessible published attachments. They cannot be independently promoted to the older file pool. File metadata, versions, download, chunk grants and peer sources all enforce the document's current read/write permissions. Losing friendship immediately revokes new access to friends-only documents and their bytes.

Markdown links to uploaded attachments use `[name](linknestx-file:VERSION_UUID)`; images use `![description](linknestx-file:VERSION_UUID)`. Renderers resolve these only within the owning document. External HTTP(S) links remain ordinary links and are not P2P downloads. `GET /documents/{id}/attachments/{versionID}/preview` serves authenticated PNG/JPEG/GIF/WebP only, at most 10 MiB; it rejects HTML/SVG, sets `nosniff` and `no-store`, and rechecks authorization while streaming. Other browser downloads use the existing `/web/files/{versionID}/download` route and retain its 1 GB/one-active-stream restriction. Browser uploads and native P2P routes remain unavailable.

Document and attachment changes emit the existing content-free `files.changed` invalidation. Consumers reload authorized document/file views after these events and after local writes; private document identifiers are not broadcast globally.
