# 批次 3 实施计划（删除好友连带私聊 / 免登录 / 全局动画体系）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地批次 3 三个需求：A 删除好友时在同一事务里连带删除双方的私聊会话与消息记录（客户端提供 hover 按钮 + 滑动删除双入口与内联确认）；B 免登录（session.rs 落盘 `session-{owner}.json`，Windows 现代壳 DPAPI 加密、legacy/macOS 明文 0600 降级，`restore()` + `session_restore` 命令 + 前端 restoring 态防登录页闪烁，双壳）；C 全局动画体系（framer-motion 11.18.2 唯一动画库：MotionConfig 根、视图栈切换、列表 layout/stagger、对话框、气泡微交互、滑动删除手势、reduced-motion 全局降级）。

**Architecture:** 服务端只改 `social.Delete` 为单事务清理（friendships → 按 pair 找 direct_conversations → 逐会话删 messages/group_members/direct_conversations，groups 行保留以规避 files 外键 RESTRICT，提交后按会话补发 `conversation.changed`）；session.rs（两壳共享源码）新增落盘/restore，DPAPI 封装在 `auth/secrets.rs` 用 `#[cfg(all(windows, not(feature="legacy-host")))]` 切换——src-tauri 的 windows crate 是 target 门控依赖、legacy crate（默认 feature `legacy-host`）自动走明文分支，**零 Cargo 依赖变更即可双壳编译**；前端动画收敛到新 `client/src/motion/` 模块（`MOTION_ENABLED = import.meta.env.MODE !== 'test'` 门控 initial/exit，jsdom 测试环境渲染最终态），常驻页（消息/文档）改 grid 叠层 + 内联 style opacity/visibility 过渡，条件页（文件/传输/管理/设置）用 AnimatePresence + motion.div，滑删阈值 -64px 提取纯函数便于单测。

**Tech Stack:** Go 1.26（SQLite 事务、`net/http`）、React 18 + vitest + @testing-library/react + framer-motion 11.18.2（exact pin）、Tauri 2（windows crate 0.62.2 `Win32_Security_Cryptography` DPAPI）、legacy Electron shell（node:test、`legacy-host` feature）。

### 计划内偏离 spec 的点（已论证，执行时不要"纠正"回 spec 写法）

1. **删除后旧会话路由返回 403 而非 404**：spec 写"消息 GET 404 / 既有 403 用例改 404"，但 chat ACL（`RequireMember` → `memberInTransaction`）只有 403 分支，`chatError` 无 404 映射；且 `groups` 行可能因 files 外键保留，"会话不存在"与"无权访问"无法区分。客户端会话列表已移除该会话，仅过期缓存会命中旧 ID，UI 对 403 同样退出会话。openapi 的 404 描述保留（会话 ID 不存在场景仍适用）。
2. **`groups` 行保留**：`files.group_id` 对 groups 是 RESTRICT 外键、files 的 CHECK 不允许挪走群文件（批次 2 已论证过同款约束）；direct 会话里发的文件必须存活（保留行后因成员/直聊行已删而不可达，管理员仍可管理）。与批次 2"解散不删 groups 行"先例一致。spec 步骤 3 没列 groups，按"不动"执行。
3. **`TestDirectFilesDenyAdminManagementAndPeerSources` 的 manifest 断言 200 → 403**：该测试在 DELETE 好友后断言旧私聊文件 manifest 仍可读——那是"只删友谊、保留会话"的旧行为；本批删除 direct 行后 ACL 拒绝（文件行与版本仍保留，仅不可达）。更新断言并加注释。
4. **framer-motion 测试门控 `MOTION_ENABLED`**：jsdom 下 framer 会同步渲染 `initial`（如 opacity:0 内联样式），`toBeVisible`/`getByRole` 会立即命中半初始态，且 vitest 不加载 CSS 文件（类驱动的 visibility/animation 全部失效）。门控后测试环境渲染最终态，与 spec"jsdom 跳过动画渲染"意图一致但机制确定。
5. **exit（离场）动画只用于好友行**：AnimatePresence 离场会让元素在 a11y 树滞留 ~160ms（opacity 不影响 role 查询），既有用例（如 v031-messaging 的筛选后 `queryByRole(...).not.toBeInTheDocument()` 即时断言）会破。会话行/传输卡/群成员行只加 `layout` 与入场 stagger。
6. **radix Dialog 只做 `data-state=open` 入场 CSS 动画**：radix 在 closed 时瞬时卸载（除非 forceMount 改挂载语义），退出动画不做。
7. **常驻页切换用内联 style 而非 CSS 类做 opacity/visibility 过渡**：vitest 不加载 CSS（css 默认不处理），类驱动 visibility 在 jsdom 永不生效会让 `getByRole` 查到已隐藏页；内联 style 让 jsdom 的 `getComputedStyle` 与 testing-library 的可见性判定和真实浏览器一致。布局部分（grid 叠层）仍走 motion.css。
8. **`--ln-motion-fast` 保持 140ms**：它已被按钮等既有微交互引用，全局改 180ms 会连带改动无关视觉；spec 的"与 tokens 对齐"落实为 motion.css 新规则统一引用该 token，framer 进出场独立用 180ms。
9. **CSS hover 位移只作用于未被 framer 接管 transform 的元素**（`.doc-feed-card`、`.ln-transfer-card`）：framer 元素静止时可能残留内联 `transform:none`，叠加 CSS hover transform 会被覆盖；`.ln-button:active` 缩放不受影响（未 motion 化）。
10. **滑删手势不测 drag 过程**：framer pan 手势依赖 PointerEvent + setPointerCapture，jsdom 不可靠；测纯函数 `swipeDeleteTriggered` 阈值 + hover 按钮删除路径，drag 视觉留手动验收（Task 15 清单）。
11. **restore 多账号规则**：spec 未定义多 `session-*.json` 并存时选哪个；定为 mtime 最新（最近登录优先），测试覆盖单文件场景。
12. **existing Rust 明文扫描测试加 `#[cfg(windows)]` 门**：`go_shaped_session_...` 断言 root 下任何文件不含明文 refresh token——Windows（DPAPI）下依旧成立；macOS 按设计是明文 0600，必须跳过该断言。

替换为：

```go
func (s *Service) Delete(ctx context.Context, actor, other string) error {
	if e := s.auth.ValidateActor(ctx, actor); e != nil {
		return e
	}
	lo, hi := pair(actor, other)
	tx, e := s.db.BeginTx(ctx, nil)
	if e != nil {
		return e
	}
	defer tx.Rollback()
	if _, e = tx.ExecContext(ctx, `DELETE FROM friendships WHERE pair_low=? AND pair_high=?`, lo, hi); e != nil {
		return e
	}
	// Only the pair's direct conversations go: shared group memberships stay.
	// The groups row itself is retained because files hold RESTRICT foreign
	// keys to it; with members and the direct row gone it is unreachable.
	direct := []string{}
	if rows, e := tx.QueryContext(ctx, `SELECT group_id FROM direct_conversations WHERE pair_low=? AND pair_high=?`, lo, hi); e == nil {
		for rows.Next() {
			var id string
			if rows.Scan(&id) == nil {
				direct = append(direct, id)
			}
		}
		rows.Close()
	}
	for _, id := range direct {
		if _, e = tx.ExecContext(ctx, `DELETE FROM messages WHERE group_id=?`, id); e != nil {
			return e
		}
		if _, e = tx.ExecContext(ctx, `DELETE FROM group_members WHERE group_id=?`, id); e != nil {
			return e
		}
		if _, e = tx.ExecContext(ctx, `DELETE FROM direct_conversations WHERE group_id=?`, id); e != nil {

		}
	}

		return e
	}

		for _, id := range direct {
			s.hub.NotifyConversation(id, chat.Event{Type: "conversation.changed"})
		}
	}
	return nil
}
```

//! At-rest protection for the persisted login file. The modern Windows shell
//! seals it with DPAPI (user-scoped, no UI prompt); the legacy Win7 shell and
//! macOS fall back to plaintext behind owner-only file permissions, matching
//! how the device file is already treated.

#[cfg(all(windows, not(feature = "legacy-host")))]
mod platform {
    use crate::{Result, TransferError};
    use windows::core::PCWSTR;
    use windows::Win32::Foundation::{HLOCAL, LocalFree};
    use windows::Win32::Security::Cryptography::{
        CRYPTPROTECT_UI_FORBIDDEN, CRYPT_INTEGER_BLOB, CryptProtectData, CryptUnprotectData,
    };

    fn blob(bytes: &[u8]) -> CRYPT_INTEGER_BLOB {
        CRYPT_INTEGER_BLOB {
            cbData: bytes.len() as u32,
            pbData: bytes.as_ptr() as *mut u8,
        }
    }

    /// DPAPI allocates the output buffer with LocalAlloc; take copies ownership.
    fn take(output: &mut CRYPT_INTEGER_BLOB) -> Vec<u8> {
        if output.pbData.is_null() || output.cbData == 0 {
            return Vec::new();
        }
        let bytes =
            std::slice::from_raw_parts(output.pbData, output.cbData as usize).to_vec();
        let _ = LocalFree(Some(HLOCAL(output.pbData as *mut _)));
        *output = CRYPT_INTEGER_BLOB::default();
        bytes
    }

    pub fn protect(data: &[u8]) -> Result<Vec<u8>> {
        unsafe {
            let mut output = CRYPT_INTEGER_BLOB::default();
            CryptProtectData(
                &blob(data),
                PCWSTR::null(),
                None,
                None,
                None,
                CRYPTPROTECT_UI_FORBIDDEN,
                &mut output,
            )
            .map_err(|_| TransferError::new("无法加密本地登录状态"))?;
            Ok(take(&mut output))
        }
    }

    pub fn unprotect(data: &[u8]) -> Result<Vec<u8>> {
        unsafe {
            let mut output = CRYPT_INTEGER_BLOB::default();
            let mut description = windows::core::PWSTR::null();
            CryptUnprotectData(
                &blob(data),
                Some(&mut description),
                None,
                None,
                None,
                CRYPTPROTECT_UI_FORBIDDEN,
                &mut output,
            )
            .map_err(|_| TransferError::new("无法读取本地登录状态"))?;
            if !description.is_null() {
                let _ = LocalFree(Some(HLOCAL(description.as_ptr() as *mut _)));
            }
            Ok(take(&mut output))
        }
    }
}

    /// Atomic write (temp file + fsync + persist) of the encrypted session,
    /// owner-scoped like the device file. Unix also pins 0600.
    fn persist_session(&self, current: &NativeSession) -> Result<()> {
        let payload = serde_json::to_vec(&StoredSession {
            origin: current.origin.clone(),
            session: current.session.clone(),
        })?;
        let sealed = secrets::protect(&payload)?;
        let path = self.session_file(&current.owner());
        let mut file = tempfile::NamedTempFile::new_in(&self.root)?;
        use std::io::Write;
        file.write_all(&sealed)?;
        file.as_file().sync_all()?;
        file.persist(&path)
            .map_err(|_| TransferError::new("无法保存登录状态"))?;
        #[cfg(unix)]
        {

            let _ = std::fs::set_permissions(&path, std::fs::Permissions::from_mode(0o600));
        }

    /// Reads, validates and re-authenticates the newest stored login. Any
    /// rejection removes the file so the next start goes straight to the
    /// login screen instead of retrying dead credentials.
    pub async fn restore(&self) -> Result<Session> {
        let path = latest_session_file(&self.root)
            .ok_or_else(|| TransferError::new("没有可恢复的登录"))?;
        let stored: StoredSession = match std::fs::read(&path)
            .map_err(TransferError::from)
            .and_then(|sealed| secrets::unprotect(&sealed))
            .and_then(|plain| serde_json::from_slice(&plain).map_err(TransferError::from))
        {
            Ok(value) => value,
            Err(_) => {
                let _ = std::fs::remove_file(&path);
                return Err(TransferError::new("登录状态已失效"));
            }
        };
        if stored.session.user.id.is_empty()
            || stored.session.access_token.is_empty()
            || stored.session.refresh_token.is_empty()
            || stored.session.user.disabled
        {
            let _ = std::fs::remove_file(&path);
            return Err(TransferError::new("登录状态已失效"));
        }
        let origin = self.login_origin(&stored.origin)?;
        let _guard = self.refresh.lock().await;
        let candidate = NativeSession {
            origin,
            session: stored.session,
        };
        // rotated() validates identity/device against the server and persists
        // the refreshed tokens on success.
        match self.rotated(&candidate).await {
            Ok(current) => {
                *self.state.write().await = Some(current.clone());
                Ok(current.session)
            }
            Err(error) => {
                let _ = std::fs::remove_file(&path);
                Err(error)
            }
        }
    }
