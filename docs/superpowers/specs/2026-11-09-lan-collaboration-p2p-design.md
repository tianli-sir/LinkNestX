# 局域网与公网协作传输系统设计

## 意图

为内部员工提供一个自托管的桌面协作系统。员工在办公室局域网内可以高效聊天和多源并行传输文件，在家中也可以通过公网地址登录并继续使用。服务器保存聊天、文件元数据、文件池资源和审计记录；员工设备在获得授权且客户端在线时，互相提供文件分片，从而减少服务器出口带宽并提高下载速度。

系统的主要入口是 Windows 和 macOS 桌面客户端。客户端界面使用 Web 技术开发并打包为桌面应用，登录、群聊、文件浏览、上传下载和 P2P 都在同一个应用中完成。主窗口关闭后，后台传输模块继续下载和共享分片。第一版不提供员工使用的浏览器登录端。

## 用户与使用场景

- 首期规模基线约为 100–200 个员工账号，最大单文件 20 GB；不设固定吞吐、延迟或 P2P 成功率指标，具体并发和缓存参数保持可配置。
- 内部员工使用账号登录桌面客户端，在部门群或项目群中聊天和协作。
- 员工在办公室时，客户端发现同一网络中的授权节点并优先使用局域网直连。
- 员工在家时，通过公网地址连接服务器；客户端尽可能与其他授权客户端建立公网直连，失败后使用服务器中继或直接从服务器下载。
- 管理员创建账号、群组和群主，管理所有文件和审计记录。
- 群主维护本群成员和群文件。
- 管理员把群组中的临时文件提升到公共池；公共池中的文件对所有已登录员工可见和可下载，并由管理员长期维护。

## 目标

1. 提供稳定的群聊和文件协作体验。
2. 实现服务器保存完整副本、客户端多源分片并行下载的混合传输模式。
3. 在局域网和公网都尽可能使用授权节点之间的加密直连。
4. 直连失败时自动回退到中继或服务器下载，不能让 P2P 失败阻塞任务。
5. 支持断点续传、分片校验、动态调度和客户端后台做种。
6. 让管理员能管理账号、群组、公共池、文件版本、过期策略和审计记录。
7. 让普通群文件自动过期，避免临时文件长期占用服务器和员工设备。

## 非目标

- 第一版不提供匿名公开下载，所有资源都要求已登录员工访问。
- 第一版不提供独立的员工浏览器端；浏览器不是文件传输节点。
- 第一版不做端到端加密。服务器可以读取内容，以支持文件池管理、搜索、审计和清理。
- 第一版不把客户端做成永久公网服务器；客户端只在应用运行且用户未暂停共享时提供分片。
- 第一版不接入企业微信、钉钉、LDAP 或 Active Directory；账号由管理员在系统内创建。
- 第一阶段不实现私聊、群公告等次要消息能力，先完成群聊与文件协作。

## 已确定的产品规则

### 账号与角色

- 管理员手动创建员工账号，设置初始密码；员工首次登录后修改密码。
- 账号密码是基础登录方式；验证码或双因素认证作为可配置增强项。
- 管理员可以禁用账号、重置密码、撤销会话和强制所有设备重新登录。
- 管理员创建群组并指定一个或多个群主。
- 群主维护本群成员和本群文件；普通成员不能越过群组权限访问文件。
- 管理员管理全局账号、群组、文件、公共池、版本和审计记录。

### 群聊与文件

- 第一阶段重点是群聊、群文件和公共池。
- 群成员可以在有权限的群组中发送消息、上传文件和下载文件。
- 上传者可以管理自己上传的普通文件；群主可以管理本群文件；管理员可以管理所有文件。
- 文件消息关联文件对象和版本，消息中显示文件名称、大小、版本、状态和下载进度。
- 后续可在同一消息模型上增加私聊、群公告、@成员、置顶、搜索和更细的通知。

### 文件池与生命周期

- 普通群文件默认保留 30 天，到期直接删除文件本体和分片，不进入回收站。
- 删除后，聊天消息可以保留“文件已过期删除”的标记；文件元数据和操作记录按保留策略保存。
- 管理员可以把任何群文件提升到公共池，保留原文件哈希、版本和历史记录，不重复上传。
- 公共池文件不受 30 天期限影响，长期保存，由管理员发布、编辑、替换版本、下架和删除。
- 公共池文件对所有已登录员工开放，不继承原群组权限，也不提供匿名链接。
- 客户端应在文件过期或管理员删除后清理本地缓存分片。

### 记录保留

- 聊天消息保存两年，到期自动清理正文和附件引用。
- 文件上传、下载、删除、权限变更、公共池提升、版本变更和 P2P 传输记录保存两年。
- 审计记录至少包含操作者、时间、对象、动作、结果和必要的来源设备信息。

### 客户端后台行为

- 客户端默认随 Windows/macOS 启动并在系统托盘运行。
- 关闭主窗口不会退出后台传输模块；用户明确退出客户端后才停止下载和共享。
- 下载完成后，客户端默认继续为有权限的员工提供分片。
- 客户端可以临时暂停共享，但管理员可以对公共池文件和群组设置共享策略。
- 客户端应显示当前下载、上传、共享状态，并允许设置带宽和并发上限。

## 系统形态

### 桌面客户端

桌面客户端包含以下模块：

1. 登录、会话和设备管理。
2. 群组列表、群聊和消息同步。
3. 群文件与公共池浏览、搜索和版本查看。
4. 文件上传、下载任务和断点续传。
5. P2P 节点发现、分片调度、连接管理和哈希校验。
6. 系统托盘、后台任务、通知和带宽控制。
7. 管理员界面：账号、群组、公共池、策略和审计记录。

界面采用 Web 技术，打包为 Windows 和 macOS 桌面应用。实现时优先评估 Tauri；如果所需 P2P 或系统后台能力在 Electron 中更成熟，则使用 Electron。核心传输逻辑应放在可测试的本地服务层，避免和 UI 框架绑定。

### 服务器

服务器只需提供 API 和传输服务，不提供员工浏览器登录页面。主要服务包括：

- 身份认证、会话、账号和角色。
- 群组、成员、消息和文件元数据。
- 公共池、文件版本和生命周期任务。
- 分片哈希、节点拥有关系和下载任务协调。
- P2P 信令、连接协商和中继入口。
- 服务器文件存储和缺失分片补源。
- 审计日志、统计和管理接口。

服务器作为权威元数据源和长期文件种子。首期按用户自有的单机服务器和公网入口设计，不把云厂商、硬件型号、高可用集群或固定服务等级作为前置条件。目录、并发数、分片大小、缓存和中继策略全部配置化，未来再拆分数据库、文件存储和传输服务。

## 文件传输设计

### 文件对象

每个文件对象包含稳定的文件 ID、名称、大小、媒体类型、创建者、所属群组或公共池、版本、过期时间、访问策略和整体哈希。文件被切成固定大小或按配置生成的分片，每个分片保存索引、大小和哈希。版本之间可以共享相同分片，避免重复存储。

### 下载流程

1. 客户端向服务器请求文件元数据、版本和分片清单。
2. 客户端向服务器报告本机已有的分片和网络能力。
3. 服务器返回有权限且拥有目标分片的候选节点。
4. 客户端优先尝试局域网或公网直连，并把不同分片分配给多个来源。
5. 直连失败时，尝试配置的中继；中继失败时从服务器请求分片。
6. 每个分片下载后立即做哈希校验，错误分片丢弃并降低来源节点可信度。
7. 全部分片完成后校验整体哈希，原子化合并为目标文件。
8. 客户端继续向服务器报告已拥有分片，并默认参与后续授权下载。

调度器应根据来源速度、连接延迟、失败率、节点负载和服务器压力动态调整分片任务。单个来源掉线不应导致整个任务失败，未完成分片要能快速转移到其他来源。

### P2P 网络

- 服务器负责设备身份、授权、节点发现、分片清单和连接信令。
- 节点之间使用加密连接，并在传输前验证双方账号、设备会话和文件访问权限。
- 先尝试同一局域网直连，再尝试跨公网直连；直连技术可以采用 QUIC/WebRTC DataChannel 或成熟的 P2P 库，具体选型在实现计划中验证。
- 需要中继时，服务器只转发加密数据并计量流量；服务器仍可在需要时直接提供文件分片。
- P2P 只传播经过哈希验证的分片，节点不能凭空宣布拥有未验证内容。
- 文件权限、群组成员变化、公共池下架和普通文件过期应立即影响后续分片请求。

## 安全与信任边界

- 所有客户端和服务器连接使用 HTTPS/TLS；节点直连和中继使用加密传输。
- 密码使用强哈希保存，初始密码首次登录强制修改；会话支持过期、撤销和设备列表管理。
- 服务器可以读取文件和聊天内容，便于搜索、审计、文件池管理和过期清理；文件在磁盘上仍应加密保存或使用受保护目录。
- 服务器不向未登录请求返回文件元数据或分片。
- 每次分片请求在服务器或签发的短期授权令牌中绑定用户、设备、文件版本和过期时间。
- 审计记录不可由普通员工修改；管理员删除公共池文件也要记录。
- 客户端需要限制本地缓存目录权限，并在文件过期、权限撤销或管理员删除后清理缓存。

## 第一阶段范围

第一阶段交付一个可运行的自托管系统：Windows/macOS 桌面客户端、服务器 API 和单机文件存储，按约 100–200 个账号和最大 20 GB 单文件作为验证基线。功能包括本地账号、管理员和群主角色、群组聊天、群文件、公共池、30 天文件过期、两年聊天与审计保留、后台做种、局域网 P2P、跨公网直连尝试、中继/服务器回退、断点续传、分片校验和基础管理界面。

第二阶段再增加私聊、群公告、全文搜索、@成员、消息置顶、通知策略、更多版本比较和更细的设备/带宽管理。

## 设计成功标准

- 员工只安装桌面客户端即可完成登录、群聊、上传和下载，不需要浏览器登录。
- 同一文件被多个员工持有时，新下载能并行使用多个授权来源，并在来源离线时自动切换。
- 关闭客户端主窗口后，后台下载和做种仍然继续；明确退出后停止共享。
- P2P 连接失败不会阻塞下载，服务器始终可以提供完整文件。
- 普通文件到期自动删除，公共池文件不会被生命周期任务误删。
- 管理员能解释任何文件何时上传、何时进入公共池、谁下载过、哪些节点参与过传输。
