# LinkNestX 0.2：聊天、Web 和桌面体验改版

## 目标和授权

用户要求先在本地开发，明天再更新服务器。本次不连接、不部署或修改 `192.168.31.41`，不改变既有服务、Nginx 和任何生产数据。沿用 Go/SQLite 服务与 React/TypeScript/Tauri/Rust 客户端，保持 Windows x64 与 macOS 支持，沿用 team 模式开发。保留当前已交付版本和大量尚未提交的文件及其暂存状态。

用户已确认：Web 登录、群聊/私聊、文件浏览和单个不超过 1,000,000,000 字节的下载；Web 不上传文件、不参与 P2P、不提供后台传输或自动更新。好友申请获同意后才能私聊。客户端默认后台下载增量更新，校验后提示重启，传输期间延迟安装，增量不可用时回退经过同等验证的完整版本。新增已读。桌面默认 P2P，不能通过产品设置关闭，不显示共享开关或技术状态。服务器地址内置，只有软件更新能改变。

本次增加真实能力与可扩展模块边界；企业知识库是后续方向，本期不增加空页面或假入口。

## 用户可见结果

- 主界面是紧凑的 IM 工作区：消息、联系人、文件、传输；管理员另有管理入口。会话栏显示头像、名称、摘要与未读数，中间是聊天；资料以抽屉打开。
- 每个员工有不可变、唯一、8 位起的数字账号，内部 UUID 保留；支持数字账号和原用户名登录。点击头像可看展示名、账号和好友关系，按号码搜索/申请，接受后聊天。员工可在桌面设置头像及展示名，Web 可查看。
- 私聊与群聊共用消息与文件卡片。拖拽、文件选择和主动粘贴文件/截图进入待发送列表，允许移除，点击发送后上传；普通文字粘贴保持原行为。多文件独立失败/重试，未完成文件不发布为可下载消息。
- 上传、下载的进度在对应文件卡片上显示，传输中心有清晰的全量任务列表。显示当前速率、预计剩余、总用时及平均速率，暂停/哈希/校验/零字节/历史数据未知时不显示假数字。
- 私聊自己的消息显示未读/已读；群消息显示已读人数，可打开名单。仅当前会话处于前台且消息实际可见时上报；后台接收、历史预加载和跳过的消息不自动变成已读。
- 登录仅填写账号和密码，当前桌面服务器固定为 `http://192.168.31.41:18080`。Web 使用自身同源服务器。离线显示连接失败与重试，不让员工改服务器。未来公网地址随新客户端版本内置。
- Web 提供真实的客户端下载入口，登录后有轻量客户端引导；超 1 GB 文件提示使用客户端，不进入下载流。浏览器的普通下载由浏览器管理，其操作系统下载行为不能承诺关标签立即停止。

## 界面设计

使用用户指定的 ui-ux-pro-max，调查和检索记录见 `.cache/next-release/ui-recon.md`。采用主导航约 68px、会话栏约 296px、弹性聊天区，窄屏单栏带明确返回。保持系统中文字体，不下载字体。青绿主色 `#0F766E`，浅青绿选中态，白色与浅灰背景；通过间距、细分隔与字体层级组织信息，不堆叠仪表盘式卡片。头像、发送按钮、消息气泡和文件卡片具有统一视觉语言。

所有图标按钮有名称、键盘焦点可见；提供文件选择替代拖拽；移动布局没有横向溢出。消息正文安全文本渲染；长文件名和账号不会撑破布局。动态速率不会持续打断屏幕阅读器。聊天滚动保持用户当前位置，查看历史时通过“新消息”按钮回到底部。使用真实 UI 截图验证桌面和窄屏，并区分测试夹具与真实服务联调。

## 服务端与数据边界

### 身份、好友和私聊

新增资料、好友申请/关系、私聊会话映射以及读取记录的可回滚前向迁移；不修改历史迁移。既有用户自动获得账号编号和默认展示名，账号分配须事务安全且避免与已有数字用户名产生登录歧义。新建账号也经过相同分配规则。头像仅 PNG/JPEG，输入最多 2 MB，解码前限制尺寸，转为最多 256px 的规范图片；拒绝 SVG/外链。默认头像由名字与稳定配色生成。

申请状态包括 pending/accepted/rejected/cancelled，重复请求幂等；只能由接收者同意/拒绝、发送者撤回，禁止申请自己或停用员工。好友对为有序规范化的唯一组合。删除好友保留旧历史但禁止新的私聊发送及文件上传，重新互加后可继续。每对好友只有一个私聊会话。

复用内部群成员/消息/文件设施时，必须给私聊明确的类型和封闭成员规则：群列表与群管理不能枚举或变更私聊；群管理员的管理权限不能读取私聊消息/文件或回执；普通第三人同样不能。既有群成员权限、普通文件 30 天、公共池永久、聊天和审计两年保持。管理员仍可管理群文件和公共池；私聊文件不通过管理员全局文件索引泄露。

### 消息与已读

提供统一会话列表/最近历史页/向前分页与增量同步接口，同时兼容既有群消息接口。消息 ID、sequence 和 clientMessageId 保持幂等身份。会话投影含 lastMessage 和 unreadCount；新消息、好友变更、资料变更和已读通过现有实时通道更新，重连以服务器数据补齐。

采用实际可见 messageIds 的去重读取记录，每批最多 100 条。服务器验证会话和消息权限，重复/乱序请求只能增加已读集合；不得用最大的可见 sequence 抹去中间未读空洞。自己发的消息不计入未读和已读人数。群回执按当前有权阅读的启用成员展示，列表和人数使用同一过滤条件；离群或停用者的名字不向无权限用户暴露，旧记录仍保留供其恢复权限后幂等处理。这里选择“当前可访问成员”的统计口径，避免伪造历史成员快照；群人数随成员变化可变化。消息过期后按既有保留规则清理对应记录。

前端在前台、有焦点、活动会话且消息首段位于可见滚动区约 400ms 后合并上报。模态遮罩期间暂停上报。只有服务器确认的回执用于向发送者显示已读。跨设备取并集，取消订阅后的响应不得污染新会话。

### Web 会话和下载

新增浏览器会话类型，服务器保存会话能力并在每次请求检查，不仅隐藏按钮。登录/刷新使用 HttpOnly、SameSite cookie；HTTPS 设置 Secure，已授权局域网 HTTP 允许对应 cookie。写操作及 WebSocket 检查同源 Origin，CSRF 防护不得仅依赖前端。长期令牌不放 URL/localStorage，日志不记录凭据。桌面 Bearer API 继续兼容；不能拿 Web 凭据调用桌面上传/P2P/管理写接口来绕过限制。Web 仅支持已确认的协作能力及必要账户密码操作、好友操作和回执，头像修改在桌面。

新增经过当前权限检查的整文件流下载，逐块读出，不在服务器或浏览器一次性拼出 1 GB 内存对象。下载前强制大小上限与会话同时一个下载的限制，文件名安全 Content-Disposition。下载中撤销/过期停止后续块；断开连接释放占用。浏览器下载失败/启动必须诚实显示，不能将点击链接当作保存成功。客户端安装包是公开发布资产；员工文件始终要求登录和访问权限。

## 原生文件输入与传输

统一文件选择、原生拖放、主动剪贴板操作为短期不透明 sourceHandle，绑定当前账号/会话代际，只能由可信原生入口创建。渲染层不能通过提交任意路径来获得读文件能力。用户复制文件的 Windows CF_HDROP、macOS 文件 URL 与截图图片分别处理；图片创建自有临时文件，取消/完成/过期可清理，绝不删除用户原文件。限制一次 20 个文件、每个 20 GB；文件目录不递归发送。仍保留选择按钮。

任务快照向后兼容新增 metrics、groupId（内部会话 ID）、关联附件或消息标识。统计在 Rust 引擎产生，上传 ACK 和下载哈希通过后的 bytesCompleted 仍代表逻辑进度；实时速率来自真实流量采样，恢复验证/缓存命中不能伪装新网络流量。实际有效传输字节与重试流量分开计量；平均速率按去重有效传输字节除以累计传输阶段时间，暂停不计入有效时间。总用时按累计任务执行时间显示，详情可显示含暂停的历时。旧任务缺测量数据时显示“暂无统计”。暂停清零速率与 ETA，完成冻结计时，卡顿采样衰减，时间值不为负/NaN/Infinity。任务清理/断点恢复/过期权限测试保留。

员工配置只有传输偏好（并发、限速、开机启动等），没有启停参与 P2P 的入口；旧 false/零缓存配置迁移到固定启用和正缓存预算。原生命令也拒绝关闭请求。所有正式客户端默认参与经授权的分片交换，仍可服务器回退；退出登录、权限撤销、过期、磁盘不足和程序退出必须遵守安全边界。管理员内部文件限制不可被强制 P2P 绕过。UI、托盘及设置不显示共享/P2P 技术状态。

## 真实增量更新与发布

0.2.0 首次需要手动安装：已经交付的 0.1.0 没有更新引擎，无法追溯赋予自动更新能力。之后内置更新器默认后台检查和准备更新，版本地址固定与内置服务器同源，仅允许固定更新命名空间，拒绝跨域重定向。

发布工具使用独立 Ed25519 密钥签署精确 manifest 字节。生产私钥生成在本机忽略目录，0600 权限，不提交、不放服务器或客户端；只将公钥固定进客户端。测试密钥与正式密钥分离。构建序号、产品、系统、架构、版本、过期时间、所有文件/块 SHA-256 和总长度均绑定签名。签名失败、错误平台、过期或回滚版本直接拒绝；不能以全量回退绕过签名校验。

以新版本应用负载的分块清单重构完整版本，块约 256 KiB：可从已安装版本匹配块复制，其他块由服务器下载，每块和最终全文件均校验。无旧块、旧数据损坏或增量下载失败时回退同一签名目标的完整文件；部分失败保留可验证缓存，重试有界。真实 fixture 必须证明 reusedBytes > 0 且下载量 < 全量，不能把压缩或断点续传称为增量。Windows 负载为完整应用 EXE，macOS 为完整 .app 文件树，保留模式并严禁目录穿越/逃逸链接；首次支持实际 Tauri 产物的常规文件树，遇不支持的框架链接必须拒绝并给出手动安装路径，不能静默损坏。

更新下载与聊天/用户传输隔离、低并发。准备完成提示重启；原生协调器原子阻止新任务并检查现有上传、下载、分片发送与导出，仍忙则延后，不按前端列表猜测空闲。用户同意后安全结束服务并启动可信更新助手。助手可复用当前受信程序的早期专用模式，复制到独立目录运行；不接受任意 shell 指令，安装前重验签名和负载、确认目标是当前用户可写安装位置，等待旧进程退出后同卷备份/替换/启动。新程序以本机初始化成功确认健康，网络离线不是失败；失败保留或恢复旧程序。系统级/只读位置不擅自提权，提供手动安装指引。

公开发布页从真实发布目录读取可用安装包，未发布时显示“暂未提供”而非假链接。更新清单与资产采用固定目录、内容哈希/尺寸校验和路径约束。签名发布工具、增量 fixture、部署说明在本地完成；本次不上传密钥、安装包或改动服务器发布目录。
