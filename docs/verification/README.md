常规原生测试中的两项真实 Go 联调明确标记忽略，必须由 `make smoke` / `make check` 另行强制执行。验收时曾发现 macOS 系统 Bash 对空数组的处理导致联调未启动且错误返回成功；已修正并通过复审。修正后的真实联调实际运行，传输与几何检查通过，审计 CSV 对比失败正确使整个检查返回失败。随后仅修正导出测试的时间格式预期，保留全部记录、字段、顺序及完整文件字节检查；重新获授权后，实际导出单项重跑通过（0.93 秒）。因此全部规定检查均已执行通过；最后一次完整命令中的该项失败由定向重跑闭合，并未额外重跑整组长传输。

真实导出通过原生流式下载，将服务器 205 条记录跨越 200 条的批次边界完整保存。CSV 和 JSON 逐条对照同一筛选结果，时间格式转换保留纳秒精度。临时导出文件与测试服务按预期清理。

## P2P 与文件安全

三个空缓存节点分别从不同服务器区段开始下载，并复用其他节点已验证的分块。测试使用真实 WebRTC 数据通道，覆盖 3 块与 12 块文件，以及只有一个分块暂时可发现的错峰情形。冷启动后优先复用已公布的节点内容；已有节点的混合来源调度及服务器回退保留。损坏数据、连接断开、连接过期重建、授权拒绝和取消限速等待均有运行通过的回归。

真实 Go 联调上传并下载 48 MiB（12×4 MiB）：两个节点各提供 16 MiB，服务器提供 16 MiB。下载完成前已共享首个 4 MiB，重建客户端服务后从已验证的 4 MiB 继续下载，设备撤销和缓存清理保留已保存文件均通过。该测试通过授权请求预先给两个节点准备不同分块；空缓存起步另由上述三节点测试覆盖。文件 SHA-256 为 `abe9bc53084555399e17ed60cf1ce82dbefe37e8cd078d16964a74d0ef5899e5`。

离线、退出登录和服务器临时错误时仍会删除已知过期的应用缓存与可确认归属的临时文件。有效或永久缓存、员工另存文件和无关文件保留。在线先刷新服务器期限，已提升为永久的版本不会被旧工作任务覆盖回原来的期限。

20 GB 检查验证 20,000,000,000 字节清单的 4,769 个默认分块、末块 1,558,528 字节和超限拒绝，没有实际传输 20 GB。

## 验证边界

Windows x64 的 0.1 包后续在独立 Linux 构建容器中完成编译及 PE/依赖检查，这不代表 0.2 Windows 包已构建。Windows 实机安装运行、真实公网 NAT/TURN、实际系统保存对话框及通知权限/投递、签名和公证尚未验证。Windows/macOS 的持续集成与安装包工作流已提供，但没有声称远程工作流已运行。此前开发验收阶段没有部署；后续企业环境部署不等于公网或 Windows 实机验证。

仍需在目标环境观察的恢复边界：进程在保存文件与写入完成状态之间崩溃时，已保存文件保持不动；异常的持续磁盘写入失败可能阻止任务或审计记录持久化。文件清理遇到无法确认归属的路径会保留文件并报告错误。

实施期间的范围和技术取舍及其代价见 [implementation-decisions.md](implementation-decisions.md)。
